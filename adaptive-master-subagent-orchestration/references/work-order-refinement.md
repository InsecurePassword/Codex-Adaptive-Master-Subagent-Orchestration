# AMS specialized work-order refinement

Read completely only when `work_order_refinement = true`, a non-root order has a special state-transfer or high-risk need, and no authoritative project-native packet contract supersedes it. The setting never dispatches work and this reference never replaces the canonical `runtime-core.md` WORK ORDER.

Append only fields materially required by the task:

```text
WORK ORDER ADDENDUM
Workspace / branch / worktree / starting receipt:
Retry delta: <new evidence, prior failure, and changed direction; retries only>
Detailed interface or transaction boundary: <only when the base invariant field is insufficient>
Receipt binding: <commit, tree, diff, artifact hashes, or external-action state>
Boundary recheck: before consequential action, validation, and RESULT, recheck ownership,
starting state, interfaces/invariants, acceptance criteria, and exact required validation.
```

Use this addendum for retries after material failure, dependent workspaces/stacks, recovery from an exact receipt, sensitive external actions, or high-risk state/transaction boundaries. Omit unused lines. Do not repeat identity, objective, scope, capability profile, base interfaces, validation, or return fields already present in the canonical order.

A refined order remains subject to the same worker/manager authority, one-writer safety, result envelope, routing, user-work preservation, and root-only acceptance rules.
