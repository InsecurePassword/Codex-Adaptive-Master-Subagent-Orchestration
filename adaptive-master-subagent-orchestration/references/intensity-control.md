# Normal intensity control

Read completely only when `runtime-core.md` selects a non-`auto` normal intensity. Intensity changes useful team formation, not task quality, safety, ownership, validation, or model/effort requirements. Logical reporting depth is separate from physical Codex session topology; the root may physically spawn every session while AMS records manager-worker relationships.

`balanced` is the runtime name. Persisted settings use `moderate` as the compatibility token; both select the same behavior. Normalize to `balanced` in memory and retain `moderate` when persisting.

| Intensity | Required posture |
|---|---|
| `minimal` | Maintain at most one active non-root session, including probes, managers, workers, integrators, reviewers, and observers. Use either a direct worker or one delegated manager doing bounded work. If a recorded logical chain requires a different session, first collect and close the active session at a useful boundary. This preserves strict root-plus-one execution. |
| `balanced` | Use the smallest useful small team and choose one shape per active wave: up to two direct non-manager sessions, or one active logical manager with up to three concurrently active non-manager descendants (normally two or three). Do not mix the shapes or add another manager layer. Probes, implementers, testers, integrators, reviewers, and observers consume worker slots; sequential replacements/follow-up remain allowed. Smaller shapes are valid; do not manufacture a manager or fill a slot. |
| `heavy` | Proactively form useful managers and parallel lanes when they materially improve speed, isolation, context control, or review. AMS defines no fixed logical depth, manager count, worker ratio, or agent ceiling; actual runtime capacity and project constraints govern. Avoid speculative or duplicate work without clear value. |
| `extreme` | Dispatch every useful ready safe lane, including deliberate high-value replication and independent validation. AMS defines no fixed logical depth, team shape, or agent ceiling; actual runtime capacity and project constraints govern. Remain cost-first and reject zero-value work. |

On a mode change, stop new dispatch inconsistent with the new posture, let safe active work reach an atomic/useful boundary, collect evidence, cancel only unsafe or now-valueless work, preserve prior lineage and issue new IDs for any required reparenting, update ownership, and continue under the new mode. Changing intensity never grants destructive authority, overlapping writers, weaker checks, unsupported models, or project-completion authority to a non-root agent.
